### 2.3 必须知道的一条：现在轮换管理员密码 = 全体会员掉线

实测：用线上签发的会员 token 反推签名密钥，**命中的是 `ADMIN_PASSWORD`**，不是 `MEMBER_TOKEN_SECRET`。
说明云托管**没有配置 `MEMBER_TOKEN_SECRET`**，会员 token 签名退化成了用管理员密码。

后果：HANDOFF 里「ADMIN_PASSWORD=laiwu2025 太弱，建议轮换」这条一旦执行，**所有会员手机上已登录的状态会立刻失效**，271 个人要重新输邀请码。

建议做法：这次发版时把 `MEMBER_TOKEN_SECRET` 配成与本地 `.env.local` 相同的值（`e6e25073...`，64 位）。配完当次仍会掉线一次（旧 token 是旧密钥签的），但之后就可以随时轮换密码而不再影响会员。**掉线一次是可控的，被密码重置打个措手不及不可控。**

## 五、本次不修、需要你拍板的 5 项

1. **类目编号乱序（唯一会让小程序难看的地方）**
   线上展示顺序是 `普拉提01 → 大器械02 → 维密03 → 私教05 → 瑜伽04`，编号 05 排在 04 前面。
   有两个都对的改法，选一个我给你执行：
   - A：编号跟随顺序 → 把私教 `num` 改 04、瑜伽改 05
   - B：顺序跟随编号 → 把瑜伽 `sort_order` 调到私教前面

2. **课时口径的三块可能重复加**
   `members.hours_*`（人工历史基线）+ 约课/出勤动态 + `trainings`（手工登记）。
   如果某节课既签到了、又被手工登记成 training，会算两遍。建议明确「以后只认签到，不再手工补登记」。

3. **`trainings` 里 `group` / `assessment` 类型的课时被整体丢掉**
   只有 `private` 能对上类目。若这两类也要计入累计，需要给它们一个归属（或单列一项）。

4. **`no_show_deduct` 这个设置没被代码读取**
   `studio_settings.no_show_deduct` 存在（当前=1），但签到接口对「未到」是写死必扣。
   今天行为没错（设置也是 1），但改了设置不会生效。要不要顺手接上？

5. **未到/迟到的扣次政策**
   PRD 写「未到扣次」，代码照做。开课前 2 小时内取消是直接拒绝（不扣次）。这两条政策要不要调。
