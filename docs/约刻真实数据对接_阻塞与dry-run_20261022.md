## 三、任务 ②：秦卓宇真实资产

### 结论：现在做不了，原因是"人可能不在约刻"

- 约刻会员导出 243 条里 **没有"秦卓宇"**（含"秦"的只有「秦倩」）。
- 秦卓宇是 2026-10-21 由 D3 数据准备脚本**新建**的试点档（见 `docs/数据准备单_试点5人_20261022.md`、`backups/D3交付清单_20261022.md`）。
- 他自己的真实累计节数：本系统 `attendance = 0`、`trainings = 0`；约刻里的数不在本地。

**所以要么**他本来就是约刻会员、只是没在这次导出里（需要重新按姓名/手机号在约刻查一次）；
**要么**他是为试点新开的档，那"约刻真实入会/开卡日期、累计节数"客观上不存在，应改为按"新会员"处理。

## 四、任务 ③：会员批量回填与对账

### 缺的数据（约刻侧）

| 需要的列 | 用途 | 约刻后台位置（据 `docs/约刻系统拆解与数据迁移_20261021.md`） |
|---|---|---|
| 姓名、手机号 | 匹配主键 | 已有 |
| 入会日期 | 回填 `members.joined_at`（现在 199 人为空） | 客户管理 → 会员信息 → 会员详情 |
| 剩余次数 / 有效期 | 回填 `member_cards` | 客户管理 → 会员卡 / 会员详情 |
| 消课流水（日期+课程类型） | 回填 `trainings`、四类课时 | 会员详情 → 上课记录 / 预约记录 |
| 卡名称、开卡日 | 回填 `member_cards.valid_from` | 会员详情 → 会员卡 |

### 本地缺的数据（仓库侧）

- 约刻导出只有两列，历史上也从未导出过卡次与流水；
- 现有 5 张会员卡（id 22–26）是 D3 试点手工开的，不是约刻真实余额；
- `trainings` 全表 **0 行**；`attendance` 0 行；`bookings` 0 行。

### 本系统内的假数据（可先清理，不依赖约刻）

| 问题 | 人数 | 说明 |
|---|---|---|
| `hours_pilates=18 / equipment=16 / fat_burn=8` | **279** | 全量占位；会员端"累计上课 42 节"就是这三项相加 |
| `total_hours=42` | **193** | 另一处占位；`scripts/cleanup-demo.mjs` 已能清这一项 |
| `joined_at` 为空 | **199** | 约刻导入时没带入会日期 |
| 占位会员名 `会员N` | 21 | `cleanup-demo.mjs` 已覆盖 |
| 演示会员 王芳 / 陈知意 | 2 | `cleanup-demo.mjs` 已覆盖（陈知意、王芳需补进正则） |

> 注意：现有 `scripts/cleanup-demo.mjs` 只清 `total_hours=42`，**没有清 `hours_* = 18/16/8`**，所以跑完它，会员端仍会显示 42 节。这是这一项必须补的地方。
