## 1. 阅读体验核心维度

### 1.1 栏宽控制（Measure）

| 对标 | 正文栏宽 | 效果 |
|------|----------|------|
| Aesop | ~520px (~32em) | 像读杂志，视线不需要大幅移动 |
| Linear | ~560px | 信息密度适中 |
| Medium | ~680px (~42em) | 适合长文但不适合快速浏览 |
| Apple 产品页 | ~490px | 极其窄，极度聚焦 |
| 纽约时报中文 | ~640px | 接近 40em |
| 徕舞现状 | 34em ~ 42em | 合理范围 |

**结论：** 中文正文字数密度比英文高，同样宽度下中文信息量更大。建议保持 34em 上限。

### 1.2 行高（Leading）

| 对标 | 行高 | 效果 |
|------|------|------|
| Aesop | ~1.8 | 呼吸感强，适合慢读 |
| Medium | ~1.6 | 标准阅读体验 |
| NYT 中文 | ~1.8-2.0 | 中文需要更高行高 |
| Apple | ~1.5 | 标题和短文案适用 |
| 徕舞现状 | 1.9 (body) / 2.0 (长文) | 偏大，适合品牌感 |

**结论：** 徕舞的 1.9 行高适合品牌气质，不需要改。但可能在某些场景（如卡片内文字）显得过松，需要区分场景。

### 1.3 段落间距

| 对标 | 段落间距 | 效果 |
|------|----------|------|
| Aesop | 1.5-2x 行高 | 段落之间有呼吸 |
| Linear | 1x 行高 + margin | 紧凑但有层次 |
| Medium | 2x 行高 | 文章感强 |

**结论：** 徕舞 FounderLetter 的 `space-y-8`（约 32px）合适，不需要改。

## 2. 标题层级节奏

### 2.1 阅读节奏概念

一个好的长页面阅读体验像音乐，有强弱拍：

```
Hero (最强拍) → 留白 → 二级标题 (中强拍) → 正文 (弱拍)
→ 留白 → 三级标题 (中拍) → 正文
→ 留白 → Hero级收尾 (强拍)
```

### 2.2 标题字号阶梯

| 层级 | Aesop | Linear | 建议徕舞 |
|------|-------|--------|----------|
| Display (Hero) | ~48px | ~56px | 5xl-9xl |
| H2 (Section) | ~32px | ~36px | 3xl-5xl |
| H3 (Card) | ~20px | ~20px | lg-xl |
| Body | ~14px | ~15px | text-sm/base |

### 2.3 标题与正文间距

- Aesop：标题下方留 24-40px 再开始正文
- Linear：标题下方留 16-24px
- 徕舞现状：`mt-12`（约 48px），偏大但符合品牌感

## 3. 中文排版特殊考量

### 3.1 中文 vs 英文差异

| 维度 | 英文 | 中文 |
|------|------|------|
| 字符密度 | 低（每行容纳 12-15 词） | 高（每行 20-30 字） |
| 行高需求 | 1.4-1.6 足够 | 1.6-2.0 更好读 |
| 字距 | 可以 tight（-0.02em） | 不宜过紧（-0.02～-0.03em 上限） |
| 对齐 | 左对齐最自然 | 左对齐，但两端对齐在窄栏下可用 |

### 3.2 标点符号

- 中文引号 「 」 或 “ ” 均可，但要统一
- 徕舞目前用 &ldquo; &rdquo;（英文引号），视觉上更干净但不符合中文排版规范

## 4. 案例展示方式分析

### 4.1 三种案例展示模式

| 模式 | 代表 | 适合场景 |
|------|------|----------|
| 列表式（纵向排列） | Aesop 产品页 | 深度阅读，逐一展开 |
| 网格式（3列卡片） | Linear 客户案例 | 快速扫读，比较 |
| 杂志式（大图+长文） | NYT 人物档案 | 沉浸式，讲述故事 |

### 4.2 徕舞当前

- CasesSection：列表式（纵向排列，一行一人）
- StoriesTeaserSection：网格式（3列卡片）

**两种模式重复了同一批数据（李女士/张女士/陈女士），是结构性问题。**

## 5. 徕舞首页阅读节奏诊断

```

```

### 问题

1. **中间段（Ecosystem → Demo）连续 7 个板块都是「功能+CTA」节奏**，像读产品说明书
2. **Journey 之后没有足够的呼吸**，直接进入 Cases
3. **BrandFilm 是节奏断裂点**（占位无内容）
4. **Stories 和 Cases 重复**，浪费了节奏空间

---

## 6. 关键建议（仅供后续 Sprint 参考）

1. Cases 和 Stories 合并为一个板块
2. BrandFilm 要么加内容，要么删除占位
3. 在 Journey 后加一个过渡留白（类似 Apple 的「section divider」）
4. 将 Ecosystem/HowItWorks/AIReport 的信息整合，减少板块数
