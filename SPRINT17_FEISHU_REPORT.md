## 3. Dedup Strategy

- **Key**: `memberCode` (飞书会员编号)
- **Exists**: UPDATE name/gender/phone/stage/tags/joinedAt/birthday
- **Not Exists**: INSERT new member with tenantId=1, status="active"
- **No memberCode or no name**: SKIP with log entry

## 8. Key Answers

### Q1: Can we rely on Feishu for 12 months?
**Yes, with caveats.** Feishu is the data entry hub for basic member info. But training records, photos, and questionnaires are NOT synced from Feishu — they're entered directly in CRM. Feishu only provides member base data (name, phone, birthday, etc.).

### Q2: Do we need Airtable?
**No.** Current volume (<500 members) is well within Feishu's capabilities. The sync via Open API is stable with token caching and pagination.

### Q3: Do we need a custom data entry system?
**Not for member base data.** But consider adding questionnaire, training, and photo sync from Feishu if coaches prefer Feishu over CRM for those operations. Currently those are CRM-only.

### Q4: Biggest risk?
**Field name mismatch.** Feishu column names (e.g., "姓名" vs "会员姓名" vs "name") may change when coaches edit the table. The `mapFeishuToMember` function tries multiple aliases, but if a new column name is used, the field will be silently dropped. A field mapping config file would mitigate this.
